## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what has been built.
2. **Infrastructure before features.** The first phase sets up project structure, Supabase, auth, design tokens, and tests so feature work can stay clean.
3. **Magic moment first.** The guided Next Day flow works before the app tries to become rules-complete.
4. **Test as you go.** Rules, state transitions, saves, and mobile UI must be verified continuously.
5. **Progressive enhancement.** Start with the simplest working version of each flow, then layer in full rules coverage and polish.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent, such as CodeRabbit, review it before starting the next phase. External review catches issues the coding agent may miss.
7. **Source fidelity is product quality.** Every implemented Miru rule should trace back to `docs/miru-rules-requirements.md` or a visually verified source note.
8. **Do not outrun rights clarity.** Build the private prototype confidently, but keep public launch, public source assets, and public Miru-branded distribution gated by permission.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections. The agent should read only those sections, not the entire PRD, vision doc, and GTM doc.
3. **Let it work:** The agent reads the roadmap, finds the first unchecked task, implements it, and marks it complete.
4. **One session = one phase when possible:** Try to complete a full phase in one session for best continuity. If you need to stop, resume from the first unchecked task.
5. **Push a PR for review:** When a phase is complete, push the work as a PR and let a review agent, such as CodeRabbit, review it before starting the next phase.
6. **Need more context?** If a task references a section not in the phase's Reference sections, read just that section on demand.

### Session Tips

- **Do not read everything by default:** The docs are intentionally large. Each phase tells you what to read.
- **Do not skip tasks:** Tasks are ordered to avoid dependency problems.
- **Verify after each phase:** Run the app and test suite before opening the phase PR.
- **Review before moving on:** External review catches bugs, security issues, and style problems the coding agent may miss.
- **Update the status line:** After completing tasks, update the header status and current phase.
- **Keep rights in mind:** Do not publish Miru-branded materials, source assets, or source-derived text publicly until permission is clear.
